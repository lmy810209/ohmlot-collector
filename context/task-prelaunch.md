# 작업 지시: 공개 전 마지막 두 가지

## A. 검증 안 된 시드 가격을 정직하게 표시한다

Booster K1의 $5,999는 출시 보도자료에서 온 숫자이고, 실제로 살 수 있는
어떤 에디션 가격과도 맞지 않는다(리셀러 $9,999.99 / $12,500 등).
`listed`로 분류해 가격 칸에는 "not tracked"가 뜨지만, **모델 레코드의
`price_usd_min/max`는 그대로 남아 있다.** 필터·정렬·상세 페이지 어딘가에
그 숫자가 노출되면 여전히 틀린 가격을 보여주는 것이다.

그리고 이건 K1만의 문제가 아닐 가능성이 높다. 시드 32종의 가격 대부분이
출시 기사에서 왔고 **우리가 확인한 적이 없다.**

### 할 일

1. 32종 각각의 `price_usd_min/max`가 어디서 왔는지 `sources[]`로 확인해
   `price_provenance`를 붙인다:
   - `observed` — 우리 수집기가 실제로 관측한 가격 (tracked 15종)
   - `vendor_page` — 판매 페이지에서 사람이 확인했고 날짜를 적었다
   - `press` — 출시 기사·보도자료에서 온 숫자. **검증 안 됨**
   - `unknown` — 출처를 못 찾겠다

2. `press`와 `unknown`인 가격은 **화면에서 숫자로 단독 표시하지 않는다.**
   상세 페이지에 쓸 거라면 반드시 이렇게 쓴다:
   > Launch price (press release, 2025-03): $5,999 — not verified, not current

3. 필터와 정렬에서 `press`/`unknown` 가격은 제외한다.
   "$20,000 이하" 필터에 검증 안 된 숫자가 섞이면 필터 자체가 거짓이 된다.

4. Booster K1은 위 규칙을 적용하고, 리셀러 에디션별 가격 차이를
   `listed_reason`에 이미 적은 그대로 유지한다. **추측으로 확정하지 않는다.**

## B. 이메일 수집을 실제로 작동시킨다

지금 "Track this robot" 버튼은 `console.log`만 찍는다.
누가 이메일을 넣어도 아무 데도 안 남는다.

### 할 일

1. Supabase에 `subscribers` 테이블:
   `email`, `model_id`(null 가능 = 전체 알림), `created_at`, `confirmed_at`(null),
   `unsubscribe_token`, `source_page`
   - RLS: **insert만 허용, 공개 read 금지.** 이메일 목록이 새어나가면 안 된다.
   - `email + model_id` 유니크 제약 (중복 가입 방지)

2. 폼:
   - 이메일 하나만 받는다. 이름·회사 받지 않는다.
   - 허니팟 필드 + 같은 IP 분당 제출 제한
   - 성공하면 "등록됐습니다. 변화가 생기면 알려드립니다." 정도로만.
     **가입자 수를 표시하지 않는다.** 0명일 때 "500명이 함께합니다"가 될 수 없다.

3. 폼 옆에 한 줄로 명시한다:
   - 무엇을 보낼 것인지 (가격·재고 변화 알림)
   - 얼마나 자주 (변화가 있을 때만)
   - 언제부터 (데이터가 쌓이면 — 지금은 아직 안 보낸다)
   - 수신 거부 방법

4. `unsubscribe_token`으로 동작하는 `/unsubscribe` 페이지를 **지금** 만든다.
   첫 메일을 보내고 나서 만들면 늦다.

5. **아무것도 발송하지 않는다.** 메일 발송 연동은 이번 범위 밖이다.
   지금은 모으기만 하고, 보낼 내용이 생겼을 때 다시 논의한다.

### 참고

LEE는 한국에 있고 방문자는 미국·유럽이다. 이 정도 규모의 "알림 신청"은
위험이 낮지만, 기본은 지켜야 한다 — 무엇을 받는지 명시하고, 수신 거부가
실제로 작동하고, 목록이 공개되지 않는 것. (법률 자문은 아니다.)

## C. 보고할 것

- `price_provenance` 분포 (observed/vendor_page/press/unknown 각 몇 개)
- `press`/`unknown` 가격이 화면 어디에 노출되고 있었는지
- 폼 제출 → Supabase 저장 → `/unsubscribe` 동작까지 실제로 한 번 통과시킨 결과
