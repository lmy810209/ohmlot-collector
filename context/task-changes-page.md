# 작업 지시: /changes 페이지 + 수집 상태 노출

수집기는 이제 믿을 만하다. 그런데 **events가 쌓이는 걸 아무도 볼 수 없다.**
LEE 본인도 못 본다. 수집이 조용히 망가져도 몇 주 모를 수 있다.

이 작업의 목적은 두 가지다:
1. Ohmlot에서 제일 흥미로운 내용(무슨 일이 있었나)을 드러낸다
2. **매일 눈으로 확인할 수 있는 건강 상태 화면**을 만든다

## 1. `/changes` 페이지

`data/events.jsonl`을 읽어 최신순으로 보여준다.

- **`observation_change: true`인 항목은 기본으로 숨긴다.** 목록 위에
  "관측 개시 N건 보기" 토글을 두고, 펼치면 회색으로 다르게 표시한다.
  숨기되 지우지 않는다 — 언제부터 무엇을 보기 시작했는지도 기록이다.
- 각 줄: 날짜 · 모델명 · 무슨 일 · 이전값 → 새값 · 출처 링크
- 이벤트 종류마다 색을 다르게 (가격 하락=up 토큰, 상승=down, 품절=amber 등
  style-guide-modern.md §1 토큰만 사용)
- **실제 이벤트가 0건이면 "아직 변화 없음"이라고 그대로 쓴다.**
  관측 개시 20건을 숫자로 부풀리지 말 것.

## 2. 페이지 맨 위에 수집 상태 카드

이게 건강 검진이다. 아래를 그대로 노출한다:

- 마지막 수집 시각 (`observed_at` 최댓값)
- **마지막 수집이 36시간 넘었으면 빨간 경고를 띄운다** ("수집이 멈춘 것 같습니다")
- 오늘 수집된 가격 포인트 수 / 소스 11개 중 성공 개수
- 기준선 진행: "Day N of 14"
- 이번 주 실제 이벤트 수 (관측 개시 제외)

## 3. 홈에서 /changes로 연결

홈에 "최근 변화" 블록을 두고 최신 실제 이벤트 3건만 보여준 뒤
`/changes`로 링크한다. 실제 이벤트가 없으면 이 블록은 아예 안 그린다.
빈 칸이나 "데이터 없음" 카드를 두지 말 것.

## 4. 하지 말 것

- 이벤트가 적다고 차트 그리지 않는다 (style-guide §6)
- 관측 개시를 실제 변화처럼 세지 않는다
- 이메일 수집, 카탈로그 정리, 필터 확장은 이번 작업에 넣지 않는다 — 다음 지시

## 5. 보고할 것

- `/changes` 스크린샷 (관측 개시 숨긴 상태 / 펼친 상태)
- 수집 상태 카드가 실제 데이터로 채워지는지
- 36시간 경고를 일부러 발동시켜 본 결과
