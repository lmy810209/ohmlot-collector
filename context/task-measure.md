# 작업 지시: 2주 측정 실험 — 가설을 믿지 말고 재본다

지금까지는 "복원 불가능한 데이터가 가치 있을 것"이라는 **믿음** 위에 시스템을 쌓았다.
이 2주는 그 믿음을 **숫자로 바꾼다.** 새 기능은 만들지 않는다.

2주 뒤에 이렇게 말할 수 있어야 한다:
> "가격은 과거의 82%를 복원할 수 있었지만 재고는 11%뿐이었다.
>  그리고 6시간 관측에서, 하루 1회였다면 놓쳤을 재고 이벤트가 24%였다."

---

## A. Internet Archive 역조사 — 필드별 복원 가능성 측정

**기한 1주. 재미있다고 늘리지 말 것.** (시간 늪 경고)

### 대상
`tracked` 15종 중 대표 5종. Unitree 2종 + 나머지 제조사 3종으로 섞는다.

### 방법
각 제품의 공식 판매 페이지를 Wayback Machine에서 과거 12개월 스냅샷으로 훑는다.
각 스냅샷에서 아래 필드가 **읽히는지** 기록한다:

| 필드 | 복원됨 / 캡처는 있는데 값 없음 / 캡처 자체 없음 |
|---|---|
| 가격 | |
| 재고 상태 | |
| 구매 경로 (buy now / preorder / quote 등) | |
| variant 목록 | |
| 할인 여부 | |
| 구성품 | |
| 보증 조건 | |
| 지역·배송 조건 | |

결과를 `context/recoverability.md`에 표로 남긴다.
**필드별 복원율(%)** 을 계산한다. 이게 이 실험의 산출물이다.

### 반드시 지킬 것
- **"캡처 없음"을 "그때 없었다"로 해석하지 않는다.** 셋을 구분해서 기록한다:
  `복원됨` / `캡처는 있으나 값 없음(JS 렌더링 등)` / `캡처 자체 없음`
- 스냅샷의 **timestamp를 반드시 기록**한다. Wayback은 인접 시점 캡처로 연결되는 경우가 있다.
- 여기서 얻은 과거 값은 `historical_reconstruction` 등급으로만 저장한다.
  **`primary_observation`과 같은 테이블·같은 화면에 섞지 않는다.**
- 과거 변화를 발견해도 `events.jsonl`에 넣지 않는다. 별도 파일에 둔다.

### 이 실험이 답하는 것
- 우리가 지금 모으는 것 중 **실제로 복원 불가능한 게 무엇인가** (추측이 아니라 측정)
- 만약 가격이 90% 복원되고 재고가 10%라면 → **재고 관측에 자원을 몰아야 한다는 근거**가 생긴다
- "우리가 수집을 시작하기 전에 이미 일어난 변화"를 발굴 → 공개 시 첫 콘텐츠 후보

## B. 수집 빈도 측정 — 하루 1회로 무엇을 놓치나

**기한 2주.**

### 방법
`tracked` 15종 중 **변동 가능성이 높은 3종만** 골라 6시간 간격(하루 4회) 관측한다.
나머지 12종은 지금대로 하루 1회.

2주 뒤 비교한다:
- 6시간 관측으로 발견한 이벤트 수
- 그중 09:17 스냅샷만 봤다면 발견했을 이벤트 수
- **놓쳤을 비율**

### 반드시 지킬 것
- **3종만.** 전체로 늘리지 않는다.
- 응답에 429나 차단 신호가 한 번이라도 보이면 **즉시 하루 1회로 되돌리고 기록한다.**
  (제조사 사이트에 부담을 주는 것은 우리 원칙 위반이다)
- User-Agent는 지금대로 식별 가능하게 유지.
- 6시간 관측분은 `data/prices/intraday/`에 따로 쌓는다.
  Git의 일일 canonical 스냅샷은 지금대로 09:17분 것 하나만 유지한다.

### 판정
- 놓친 비율이 유의미하게 높으면 → Tier별 빈도 차등 적용
- 거의 0이면 → 하루 1회로 되돌린다. 그것도 결론이다.

---

## C. 카탈로그를 Tier로 나눈다 (개수는 그대로)

추적 대상을 **줄이지 않는다.** 관측 자원만 차등 배분한다.

| Tier | 대상 | 관측 빈도 |
|---|---|---|
| A | 변동 가능성 높은 3~5종 | 실험 중 6시간, 이후 측정 결과에 따라 |
| B | 나머지 tracked | 하루 1회 |
| C | `listed` 17종 | 관측 안 함. 추적 불가 이유만 유지 |

## D. 하지 않을 것

- 새 기능 추가
- 추적 대상 확대
- 공개·홍보
- 이벤트를 지어내거나 시뮬레이션하는 것

## E. 보고할 것

3. 두 결과를 근거로 한 제안: **앞으로 무엇을, 얼마나 자주 모아야 하는가**
