# 작업 지시: 관측 가능성 조사 (이번 주 유일한 목표)

방향이 바뀌었다. 수집 대상을 "공개 정가"에서
**"그 시점에 실제로 살 수 있었던 조건"**으로 옮긴다.

판단 기준 하나:
> **이 데이터는 2년 뒤에 다시 구할 수 있는가?**
> 구할 수 있으면(MSRP, 스펙, 출시일, FCC PDF) 매일 모을 이유가 약하다.
> 구하기 어려우면(특정 날짜의 재고·리드타임·할인·판매중단 시점) 그것이 우리 자산이다.

**이번 주에는 기능을 늘리지 않는다. 무엇이 관측 가능한지만 알아낸다.**

---

## 0. 원본 응답 보관 (제일 먼저, 오늘)

지금 `data/prices/<날짜>.jsonl`에 파싱 결과만 있고 원본이 없다.
파서가 틀렸다는 걸 나중에 알아도 과거를 다시 해석할 수 없고,
하루가 지날 때마다 그날 원본은 영원히 사라진다.

- 각 소스의 응답 원문을 `data/prices/raw/<날짜>/<source-id>.json`(또는 .html)에 그대로 저장
- 압축해도 좋다. 용량이 커지면 월별로 묶는다
- 이것만 먼저 커밋하고 배포한다

## 1. 11개 소스 관측 가능성 조사

각 소스에서 아래를 **상품 페이지 응답만으로** 얻을 수 있는지 확인한다.
결제·장바구니 단계는 조사만 하고 **수집 대상에서 제외한다** (아래 3번).

| 항목 | 확인할 것 |
|---|---|
| 재고 상태 | `available` 필드 / "Add to cart" 여부 / "Sold out" 표기 |
| 재고 수량 | `inventory_quantity`가 노출되는가 (대개 숨김) |
| 리드타임 | "Ships in X weeks" 같은 문구가 상품 페이지에 있는가 |
| 할인 | `compare_at_price` 또는 정가/판매가 병기 |
| variant 목록 | 구성 옵션의 추가·삭제를 추적할 수 있는가 |
| 상품 등록일 | `published_at` |
| 지역 차이 | `?country=US` 외 다른 값에서 응답이 달라지는가 |

**이미 확인된 것**: Shopify `.js`는 variant별 `available`을 준다.
`parse.ts`가 이미 읽어 저장 중이다(1일차부터 데이터 있음). 이건 다시 조사할 필요 없다.
`compare_at_price`와 variant 목록은 같은 응답에 있는데 **지금 버리고 있다** — 확인할 것.

## 2. 결과를 `context/observability.md`에 표로 정리

소스 11개 × 항목 7개의 표를 만든다. 각 칸은 셋 중 하나:
- `있음` — 상품 페이지 응답에 있다 (근거 문자열/필드명을 함께 적는다)
- `결제단계` — 장바구니·결제에서만 보인다 → **수집하지 않는다**
- `없음` — 어디에도 없다

그리고 아래를 문장으로 적는다:
- 11개 중 몇 개에서 재고를 안정적으로 관측할 수 있는가
- 리드타임을 상품 페이지에서 얻을 수 있는 소스가 있는가 (없으면 없다고 쓴다)
- 재고·리드타임이 안 되는 소스에서 대신 관측 가능한 비복원 데이터가 있는가

## 3. 하지 않을 것

- 장바구니에 담거나 결제 단계로 진입해서 배송 견적을 긁지 않는다.
  매일 자동으로 하면 판매자에게는 재고 탐색 행위로 보인다.
  지금까지 지킨 기준(우회 안 함, 약관 안 건드림)을 여기에도 적용한다.
- 로그인이 필요한 데이터는 건드리지 않는다.
- 조사 단계에서 수집기를 고치지 않는다. **조사 먼저, 구현은 다음 지시로.**

## 4. 조사가 끝나면 보고할 것

- `context/observability.md` 표
- "재고를 안정적으로 관측 가능한 소스 N개 / 11개"
- 리드타임 확보 가능 여부에 대한 결론

이 결과에 따라 events 설계와 수집 필드가 정해진다.
**여기서 멈추고 보고한다.**

## 참고: 다음 단계에서 할 것 (지금 하지 말 것)

- `events.jsonl` — snapshot 간 diff로 **자동 생성**한다. 사람이 입력하지 않는다.
  (예: 어제 `6-8 weeks` → 오늘 `3-4 weeks` 이면 `lead_time_changed` 이벤트 생성)
  이미 9/22, 9/23 두 날짜가 있으니 diff 엔진은 바로 시험해볼 수 있다.
- 저장 형태는 파싱값만 두지 말고 근거를 함께 남긴다:
  `availability_status`, `availability_evidence`("Add to cart"), `observed_at`, `source_url`, `market`
- Robot Finder는 새 페이지를 만들지 않고 **기존 로봇 표의 필터를 키운다**
  (Under $20k / US purchasable / In stock / Humanoid / Quadruped / FCC status)
